# Output Templates

Pick the template that matches the request and input volume (see SKILL.md "Output" section). Adapt headers/length to fit — these are structures, not forms to fill mechanically.

## Single Screenshot Analysis
```
## First Impression
## Emotional Impact
## Visual Hierarchy
## Layout & Typography
## Color & Imagery
## Motion Potential
## Conversion Read
## Premium Details (or: What's Missing)
## Reusable Rules
  - Observation → Rule (2-4)
## Verdict
  One paragraph: what it's optimized for, how well it succeeds, the single biggest lever to improve it.
```

## Multi-Screenshot Comparison
```
## What I'm Looking At
  Brief archetype grouping of the set.
## Shared Patterns
  Structural commonalities across genuinely different examples.
## Key Differences
  Where the set diverges and why that matters.
## Elite Hero Design Laws
  (see references/memory-and-patterns.md for format)
## Standouts
  The 1-2 strongest examples in the set, and why.
```

## Pattern Extraction Report
Same as above but leads with the laws, used when the explicit ask is "what patterns do these share" rather than a general critique.

## Design Psychology Report
Deep-dive on Stages 2, 3, 9, 10 (emotional impact, hierarchy, motion, conversion) for one or more images — used when the user specifically asks about psychology/conversion rather than general critique.

## Hero Design Audit
Used for the user's *own* work-in-progress hero (as opposed to reference/inspiration images). Same stages as Single Screenshot Analysis, but framed as actionable audit findings with explicit before/after style recommendations, prioritized by impact.

## Hero Improvement Report
Follow-up to an Audit: concrete, prioritized list of changes (highest-impact first), each with the reasoning tied back to a named principle.

## Elite Hero Design Operating System
Used when the user wants a durable reference doc (e.g., "build me a design system from these") rather than a one-off analysis. Structure:
```
## Psychology Framework
## Layout Framework
## Typography Framework
## Spacing Framework
## Color Framework
## Motion Framework
## Interaction Framework
## Conversion Framework
## Visual Hierarchy Framework
## Premium Design Checklist
```
Each framework section should be a short set of conditional rules (Observation → Rule style), not abstract theory — grounded in what was actually seen in the analyzed images plus the knowledge framework. This output is long-form and usually warrants a saved file (.md) rather than an inline chat response — check the file-creation guidance (standalone reference doc the user will save/reuse = file).
